
## 📊 项目架构概览

你的项目是一个 **工业故障树自动生成与分析平台** ，由三大子系统构成：


| 子系统             | 技术栈                           | 核心职责                                            |
| -------------------- | ---------------------------------- | ----------------------------------------------------- |
| **LightRAG 后端**  | Python 3.10+, FastAPI            | RAG 知识库、LLM 驱动的知识抽取、知识图谱存储/查询   |
| **fault-tree-ui**  | Vue 3 + Vue Flow + mxgraph       | 故障树可视化编辑、拖拽连线、撤销/重做               |
| **lightrag_webui** | React 19 + TypeScript + Sigma.js | 综合管理界面（文档管理、图谱浏览、AI 对话、国际化） |

这是你项目的 **业务灵魂** ，Prompt 和前端逻辑都建立在这些概念之上：


| 知识点             | 说明                                                                                | 你在项目中的体现                                                                                                                                                |
| -------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **FTA 基础概念**   | 顶事件(TopEvent)、中间事件(IntermediateEvent)、底事件(BasicEvent)、逻辑门(AND/OR门) | [prompt.py:11-79](vscode-webview://1l7phltegb1bb7gps8b8i3ciftbqbj053rf3ef8maoipfevg660u/LightRAG/lightrag/prompt.py#L11-L79) 的实体抽取 Prompt 精确对应这些分类 |
| **故障传播链**     | 故障因果关系建模，多原因组合触发 vs 单一原因触发                                    | Prompt 中`resultsIn` vs `jointly_resultsIn` 的区分                                                                                                              |
| **故障树绘图规范** | 标准故障树符号体系、层次布局规则                                                    | [FaultTreeViewer.tsx](vscode-webview://1l7phltegb1bb7gps8b8i3ciftbqbj053rf3ef8maoipfevg660u/LightRAG/lightrag_webui/src/features/FaultTreeViewer.tsx) 渲染逻辑  |

## 🗺️ 建议学习路线（按优先级排序）

```
阶段 1: 业务理解（1-2 周）
  ├── 学习 FTA 故障树分析方法论
  ├── 理解顶事件/中间事件/底事件/AND门/OR门
  └── 阅读 prompt.py，理解 Prompt 的业务逻辑

阶段 2: 后端核心链路（2-3 周）
  ├── Python asyncio 异步编程基础
  ├── 阅读 operate.py 的 extract 抽取流程
  ├── 理解 BaseGraphStorage / BaseVectorStorage 抽象设计
  ├── 选择一个图数据库（推荐 Neo4j）学习 Cypher 查询
  └── 学习 FastAPI 路由组织方式

阶段 3: LLM & Prompt Engineering（1-2 周）
  ├── 熟练使用至少一个 LLM API（OpenAI/Anthropic/Ollama）
  ├── 理解 Prompt 中的实体/关系抽取约束设计
  └── 学习 Embedding 原理和向量相似度检索

阶段 4: 前端可视化（2-3 周）
  ├── Vue 3 Composition API（如果你不熟悉）
  ├── Vue Flow 节点编辑器核心逻辑
  └── React 19 + Sigma.js 图谱渲染

阶段 5: 知识图谱深度（1-2 周）
  ├── 图数据模型设计
  ├── 图算法（NetworkX / graphology）
  └── 图布局算法理解

阶段 6: 工程能力（持续）
  ├── 项目架构梳理、多存储后端机制
  ├── 测试编写（pytest / Vitest / Playwright）
  └── K8s 部署配置
```

---

 **总结** ：这个项目横跨**工业可靠性工程（FTA）→ NLP/LLM → 知识图谱 → 全栈开发 → 图可视化**五个领域，技术深度和广度都很高。如果时间有限，建议优先掌握  **FTA 方法论 + LLM Prompt Engineering + operate.py 抽取流程** ，这三者是项目的核心创新点。
