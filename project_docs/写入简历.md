# 工业设备故障树智能生成系统 — 简历技术栈整理

> 面向工业故障文本，输入顶事件，基于 **LightRAG（图增强 RAG）** 自动抽取故障实体与因果关系、构建知识图谱，并生成支持 **AND/OR 逻辑门** 的故障树，附带「规则 + 知识图谱 + LLM」三重一致性校验。

---

## 一、项目定位（一句话）

基于 HKUDS/LightRAG 二次开发，在其知识图谱抽取层之上自研「故障事件实体 + 因果逻辑（AND/OR 门）」抽取流水线，并从图谱反向构建故障树（FTA），实现规则引擎 + 知识图谱对齐 + LLM 建议增强的三重校验。

## 三、RAG（重点展开）

核心是 **LightRAG 的「双通道图增强检索」**，加上故障树场景的定制：

- **索引构建链路**：文档上传 → 按 token 分块 `chunking_by_token_size` → 实体/关系抽取 → 构建 KG + 向量化 chunk（双索引）
- **多检索模式**：`local` / `global` / `hybrid` / `naive` / `mix` / `bypass` 六种查询模式（`lightrag.py` 的 `aquery`）
- **查询流程**：Query → **关键词抽取**（high-level + low-level）→ 并行「KG 检索（实体/关系邻居）+ 向量检索」→ 上下文拼接 `_build_query_context` → LLM 生成带引用的回答
- **引用溯源**：RAG 回答强制带 `### References` 引用（最多 5 条，引用对应 chunk）
- **故障树专用检索**：以顶事件为起点做子图遍历 `get_knowledge_graph(max_depth=20)` → 距离映射（BFS）→ 边方向纠正 → 组装故障树三元组（`fault_tree/builder.py`）
- **Rerank / 缓存 / token 截断**：自研 rerank、LLM 查询缓存、上下文 token 截断策略

## 四、知识图谱 / KG（重点展开）

LightRAG 的核心数据结构是「实体—关系」知识图谱，与向量索引并行为双通道。本项目在通用 KG 之上叠加了故障树场景的图操作、管理接口与可视化。

- **KG 构建**：实体抽取 → 节点（`entity_name` + `entity_type` + `description` + `file_path`/`source_id` 溯源字段）入图；关系抽取 → 边（`source → target` + `keywords` + `description`）入图；同时实体/关系描述做向量化，形成「图 + 向量」双索引
- **存储后端抽象**（`lightrag/kg/`，`STORAGES` 注册表 + 统一接口，实现「一套代码、多后端可插拔」）：
  - 图数据库：Neo4j、Memgraph、MongoDB、PostgreSQL(AGE)、OpenSearch、NetworkX
  - 向量库：Milvus、FAISS、Qdrant、NanoVectorDB、pgvector、Redis、Chroma
  - KV / 文档状态：JSON、Mongo、Redis、PG、OpenSearch
- **统一存储接口**：`BaseGraphStorage`（`has_node` / `get_node` / `get_edges` / `get_knowledge_graph` / `search_labels` / `merge_nodes` / `merge_edges` 等），通过 `_get_storage_class` + 懒加载动态挂载
- **KG 子图检索**：`get_knowledge_graph(node_label, max_depth, max_nodes)` 从指定节点出发按深度做邻域子图遍历，是故障树生成的取数入口
- **KG 查询**：`kg_query` + 实体/关系邻居检索（`_find_most_related_edges_from_entities`、`_find_related_text_unit_from_entities` 等），配合关键词抽取实现 Query → 图节点定位
- **KG 管理（CRUD）**：实体/关系的创建、编辑、删除、合并（`acreate_entity` / `aedit_relation` / `amerge_entities` / `adelete_by_entity` 等），以及 label 搜索 / 热门 label / 实体存在性校验（`search_labels` / `get_popular_labels` / `check_entity_exists`）
- **图算法**（NetworkX + 自研）：BFS/DFS 邻域遍历、距离图构建 `_build_fault_tree_distance_map`、边方向校正 `_orient_fault_tree_edge`（用 BFS 距离 + 事件层级优先级 `Basic < Intermediate < Top` 自动定向）、节点合并去重、AND/OR 门分组 `_derive_fault_tree_export_summary`
- **故障树衔接**：以顶事件为根，从 KG 子图反向生成故障树三元组（`subject/object` + `relation` + `confidence` + `source` 溯源），再导出为前端可渲染的 `gates/events` 结构
- **前端可视化**：Sigma.js / graphology / @react-sigma 渲染知识图谱与故障树（力导向布局、边曲线、节点边框、minimap 缩略图）

## 五、Prompt 工程（重点展开）

本项目**最出彩的自研部分**，集中在两个文件：`lightrag/fault_tree/prompts.py` 和 `lightrag/prompt.py`。

- **故障事件实体/关系抽取提示词**（`ENTITY_EXTRACTION_SYSTEM_PROMPT`）：结构化角色设定 + 明确实体类型规则 + 逻辑门约束 + 自检清单，是整套系统的核心
- **多段式 Prompt 编排**：System / User / Continue-Extraction 三段式，配 `completion_delimiter` 完成标记做**续抽与纠错**（漏抽、类型误判、逻辑门错误回补）
- **Few-shot 示例工程**（`ENTITY_EXTRACTION_EXAMPLES`）：3 个覆盖 OR 单因果、AND 组合事件、级联多级链路的少样本示例
- **逻辑门语义注入**：用 `resultsIn`（OR/单因果）与 `jointly_resultsIn`（AND/共因）两个受控关系词，把自然语言「和/或」逻辑转成可计算的图结构；并用「发明组合 IntermediateEvent」约束解决复杂布尔逻辑 `(A∧B)∨(C∧D)` 的平铺错误
- **输出格式强约束**：元组分隔符 `<|#|>` + 完成标记 `<|COMPLETE|>`，保证可被下游解析器直接消费
- **结构化 JSON 生成提示词**（`FAULT_TREE_JSON_PROMPT`）：schema 锁定 + 「上下文不足返回空」反幻觉约束 + 语言跟随
- **其他定制/复用的 Prompt**：RAG 引用回答、Naive RAG、关键词抽取（高/低层）、实体描述归纳（含冲突消解规则）等

## 六、抽取 / NLP（重点展开）

- **实体抽取**：从工业文本抽取「故障事件实体」，按 FTA 语义分型 `TopEvent / IntermediateEvent / BasicEvent`，并强制「可继续追溯就不能标 BasicEvent」的分层正确性
- **关系抽取**：因果方向统一为「原因 → 结果」，抽取 `resultsIn / jointly_resultsIn` 二元关系，保留中间级联链条（禁止跨层压缩）
- **实体/关系解析器**：处理 LLM 输出的元组分隔格式（`operate.py` 的 `_handle_single_entity_extraction` / `_handle_single_relationship_extraction`）
- **鲁棒 JSON 提取**：`json.JSONDecoder` + 正则回退，从 LLM 输出里稳定抠出 JSON 对象（`builder.py` 的 `_extract_first_json_object`）
- **图构建后处理**：BFS 距离图、边方向校正 `_orient_fault_tree_edge`、AND/OR 门分组 `_derive_fault_tree_export_summary`
- **故障树校验**（`fault_tree/validation.py`，38KB 自研核心）：四大维度——结构完整性 / 层级合理性 / 逻辑关系符合性 / KG 一致性，规则引擎 + KG 实体对齐 + **LLM 批量建议增强**（带超时降级），并配回归测试与业务用例

### S — 背景与目标

面向工业设备故障诊断场景，需从非结构化故障文本中自动抽取故障事件及因果关系，构建知识图谱，并生成支持 AND/OR 逻辑门的故障树（FTA），替代人工逐条梳理故障传播链的低效方式。

### A — 核心工作与技术难点

**1. 图增强 RAG 检索链路**

- **职责**：基于 LightRAG 打通「文档分块 → 实体/关系抽取 → 图 + 向量双索引 → 检索 → 生成」全链路，支持 `local / global / hybrid / naive / mix / bypass` 六种检索模式。
- **难点**：通用 RAG 返回段落式答案，无法直接产出结构化故障树，且多存储后端接口不统一。
- **方案**：以顶事件为根节点对知识图谱做限深子图遍历（`max_depth=20`），用 BFS 距离图 + 事件层级优先级（Basic < Intermediate < Top）自动校正边方向，还原为故障树三元组。
- **成果**：实现「文本 → 图谱 → 故障树」端到端生成，检索结果直接映射为前端可渲染的 `gates/events` 结构。

**2. Prompt 工程（逻辑门语义注入）**

- **难点**：自然语言中的「A 和 B 同时导致 C」「(A∧B)∨(C∧D)」等复杂布尔逻辑，LLM 极易平铺输出成错误因果边。
- **方案**：设计受控关系词 `resultsIn`（单因果/OR）与 `jointly_resultsIn`（共因/AND），通过「发明组合 IntermediateEvent」约束 + 3 组 few-shot 示例 + System/User/Continue 三段式续抽纠错，把逻辑门语义注入抽取提示词。
- **成果**：LLM 输出被约束为可计算、可解析的图结构，AND/OR 门语义正确落地。

**3. 抽取与结构化校验（NLP）**

- **难点**：LLM 抽取存在实体类型误判（把可继续追溯的事件标成 BasicEvent）、漏抽中间事件、返回非法 JSON 等问题。
- **方案**：① 实体/关系解析器处理元组分隔格式；② `json.JSONDecoder` + 正则回退鲁棒提取 JSON；③ 自研四维校验引擎——结构完整性 / 层级合理性 / 逻辑关系符合性 / KG 一致性，规则引擎 + KG 实体对齐 + LLM 批量建议增强（带超时降级）。
- **成果**：覆盖多类问题码（如 `top_event_without_gate`、`missing_edge_endpoint`、`isolated_node`），配 pytest 回归 + 业务用例防回归。

### R — 量化成果

- 打通 **13+ LLM 提供商**（OpenAI/Anthropic/Gemini/智谱/Ollama/Bedrock 等）与 **6 类图库 + 7 类向量库** 的可插拔存储抽象（`STORAGES` 注册表 + 懒加载动态挂载）。
- 支持 **PDF/DOCX/PPTX/XLSX** 多格式文档解析 + **多租户工作区隔离** + JWT 鉴权。
- 建立 **RAGAS 四维质量评估**（Faithfulness / Answer Relevance / Context Recall / Context Precision）+ Playwright E2E + pytest 回归/业务用例的完整测试体系。
