
这道赛题本质是"智能体 + 知识工程"题，评分点全在 Nexent 集成、MCP/Skills、本体构建、可溯源上， **硬件是加分项，不是评分项** 。所以正确做法不是给故障树硬塞传感器，而是让华为算力和边缘设备去服务赛题真正要求的三件事：多模态数据、低资源本体、证据可溯源。你们现有的故障树项目其实是这题的高契合底子。

**你们已有的底子**

LightRAG 的检索和图谱能力、故障树生成与结构校验、抽取提示词里的 FTA 概念，还有一份已经写好的 Nexent 重构方案文档。缺的不是方向，是把方案文档变成真正能跑的东西，以及补上赛题特别强调的两个能力：多模态和本体半自动构建。

## **需要完成的工作**

**第一，锁定"制造"场景，定义领域资产体系**。别把范围铺开，就定工业设备故障诊断。要明确三类资产：

设备资产（型号、部件、位号）

知识资产（手册、维修工单、点检表、故障代码表）

故障事件资产（顶事件、中间事件、底事件、因果关系）。

给每类资产一个统一的元数据 schema 和标识规则，这是"统一识别、理解与资产标识"的直接落点。

**Q：应该是要选择一个行业垂直领域来构建我们的模型，选择哪一个？另外最终构建的模型是否具有普适性（鲁棒性），能应用到其他行业的故障中？**



**第二，补多模态。**

这是目前最大的缺口，现在系统只处理文本。赛题说的多模态不是传感器，而是**"文本、表格、图文**"：PDF 里的设备结构图、维修照片、Excel 点检表、故障代码表。需要接入 OCR、表格解析、图文理解三个能力，把表格和图片也变成可检索、可入图的资产。

**Q：数据从哪里获取？文本、表格、图文**



**第三，做低资源知识图谱本体半自动构建。**

这是全题最有竞争力、也最符合"不被 AI 替代"的一点。定义本体：设备、部件、故障模式、现象、原因、维修措施、检测方法，以及它们之间的因果关系和 AND/OR 逻辑。流程是 LLM 提议本体 + 专家确认 + 置信度评分，从新文档和新案例里持续更新。关键是把本体对齐到真实标准，比如故障树标准 IEC 61025、可靠性分析 FMEA、设备数据标准 ISO 14224。评委看到"我们的本体对齐了某个国标/ISO"，印象分会完全不一样。

**Q：什么是本体？什么是半自动构建？**




**第四，把 MCP 工具和 Skills 真正落地。**

你们方案文档里已经列了 `parse_document`、`search_knowledge`、`extract_fault_events`、`build_fault_tree`、`validate_fault_tree`、`submit_review` 这些工具，但还没实现。**要做成 Nexent 可调用的 MCP 工具，并把故障树抽取、建模、校验、专家审核沉淀成 Skills。**"检索-推理"双驱动就是：LightRAG 负责检索召回证据，故障树生成 Agent 负责推理建树，两者通过 MCP 串起来。

**Q：如何构建MCP/Skills？**



**第五，把证据链做透。**

赛题要求"决策链路可溯源"，所以每个节点和每条边都要挂上来源：**出自哪个文档、哪一章、哪一页、哪段原文，置信度从哪来**。你们问题清单里已经发现证据字段不完整，这正好是必须补的项。

**Q：节点置信度如何量化？**



**第六，验证 Skill 可复用。**

赛题要求"沉淀可复用、可快速部署的 Skill 工作流模板"。做法是拿两类设备（比如电机和泵）各建一次知识库，证明同一套 Skill 换设备类型不用改代码，这就把"可复用"变成了可展示的结论。


**第七，部署到 Nexent 并开源。**

这个是硬性要求，中国总决赛还要开源到 GitHub 或 GitCode，要提前规划好仓库结构和脱敏。




**硬件能结合在哪**

硬件结合应该卡在这几个真实需求点上，而不是另起炉灶。

最现实的是官方给的那一卡华为云算力。**把多模态模型推理（OCR、图文理解、Embedding）和 LLM 调用放到昇腾云卡上，这本身就是硬件结合**，而且是被赛题和代金券直接支持的。你们**可以实测 CPU 和昇腾卡跑同一个 Embedding 或小模型的延迟差异，作为一个有数据的对比项。**

其次是边缘采集终端，用香橙派 AIpro 这类昇腾边缘板，把现场纸质单据、设备铭牌、维修照片拍下来，边缘做 OCR 和图像理解，再入资产库。这直接服务"挖掘行业沉睡存量数据资产"这一条，因为很多制造企业的知识恰恰是以纸质点检表、手写维修单、设备铭牌的形式躺着的。这也把你们原来的故障树从"读文档"升级成了"读现场"。

我明确不建议的一条路是：为了"有硬件"去做一个泛化的传感器 IoT 监测平台。这会让项目偏离赛题重心，把精力耗在采集和接线而不是本体和可溯源上。硬件在这里的正确角色是数据入口和算力承载，不是主菜。

**三人的分工建议**

一个人负责多模态接入和本体半自动构建，一个人负责 MCP 工具、Skills 和 Nexent 编排，一个人负责证据链、跨文档多跳推理和前端展示。老师负责对接华为云账号、代金券、算力资源，以及帮你们确认对齐的行业标准。

如果只能先做一件最能提升名次的事，我的建议是把"本体半自动构建 + 标准对齐 + 证据可溯源"这个三角做扎实，再让昇腾算力和边缘采集作为它的数据来源。这样你们的项目是一个真正跑在 Nexent 上的领域资产认知智能体，而不是"故障树系统外面套了个华为的壳"。
